The taster, rendered from the world files

Paste two things into the page. Everything after that comes from the app, so a new world puts its own taster on the site and copy can never offer a move the engine will not take.

What goes on the marketing page

<div data-yourmove-openings>
  <!-- Whatever the page says today. It stays put unless the fetch succeeds,
       so an outage leaves the page reading exactly as it does now. -->
</div>

<script src="https://YOUR-APP-HOST/embed/openings.js" defer></script>

Options

AttributeDoes what
data-yourmove-openings="the-last-hour" One world, or several comma-separated, in the order given. Omit the value for every world that has a taster.
data-yourmove-category="War & Command" Every world on one shelf. This is what a genre tab uses: a new world filed under that shelf appears there by itself, with no change to the page.
data-yourmove-limit="3"At most this many worlds.
data-yourmove-heading="h2"Heading level for world titles, so it fits the page outline. Default h3.
data-yourmove-styles="off"Bare markup, no injected CSS — style it with the site's own rules.

Styling

It inherits font and color. Four custom properties are the quick way in, and every class (.ym-world, .ym-title, .ym-tagline, .ym-prompt, .ym-choices, .ym-choice, .ym-label, .ym-preview) is a plain hook. 

[data-yourmove-openings] {
  --ym-border: rgba(0,0,0,.14);
  --ym-accent: #b4472a;
  --ym-radius: 10px;
  --ym-gap: 1rem;
}

The container also carries data-yourmove-state — loading, ready, failed, or empty — if you want to fade the swap in or hide the fallback while it loads.
